## Schema — owner: Development

**Meaning:** the payload structure changed (new schema version / checksum mismatch) and the mapping was not updated.

**Candidate causes:** `schema_drift`

**Steps:**
1. Compare the last two schema versions of the feed and list added/removed/renamed fields.
2. Check the checksum status of the affected deliveries.
3. Open a Development ticket with the diff; tell the client a fix is being prepared.

## Transport — owner: Operations

**Meaning:** the data did not arrive or arrived extremely late: upstream source or delivery endpoint problem.

**Candidate causes:** `source_outage`, `delivery_endpoint`

**Steps:**
1. Check whether other feeds from the same source also failed (source outage vs endpoint).
2. Re-trigger the delivery once; if it fails again, escalate to Operations.
3. Tell the client delivery is delayed and give the next checkpoint time.

## Content — owner: Development

**Meaning:** data arrived but incomplete: a mapping, artwork, schedule or ID problem inside the payload.

**Candidate causes:** `mapping_error`, `stale_schedule`, `image_gap`, `duplicate_ids`, `client_config`

**Steps:**
1. Measure which field is missing (artwork, schedule, IDs) using completeness by field.
2. If artwork: request assets from the client; if schedule: refresh the EPG source.
3. Escalate to Development only if the mapping itself is wrong.

## Resolve vs escalate

Resolve in Operations when the family is transport and one retry succeeds; otherwise escalate to the owner above with the generated ticket.
